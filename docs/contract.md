# Контракт: бот ↔ виджет

Виджеты — фиксированный HTML, бот их не меняет: дашборд `widgets/a.html` («Табло»)
и виджет «Инвертор» `widgets/inverter.html`. Бот отправляет виджет через `sendWidget`
и дальше меняет только состояние — строку JSON в `chat_data` (метод `editMessageWidgetData`).
Лимит `chat_data` — 1024 байта UTF-8, поэтому ключи короткие.

Ограничения Telegram для HTML (проверяет `tools/check_widget.py`, высоту — `--render`): ≤ 32768 байт и ≤ 4096 байт
после zlib-9, высота ≤ 600 px при ширине 320–430 px; нет сети и внешних шрифтов; нельзя vh, CSS nesting, `:has`,
`text-shadow`, `clip-path`, `mask`, blend modes, SVG `clipPath`/`mask`/`pattern`/`filter`.

## Дашборд: состояние (`chat_data`)

| ключ | тип | смысл |
|---|---|---|
| `r` | int | ревизия, растёт на каждом изменении |
| `g` | 0/1 | 1 — сеть есть, 0 — сети нет (квартира на батарее) |
| `s` | unix сек | когда началось текущее состояние `g` |
| `p` | сек | сколько длилось предыдущее состояние (0, если неизвестно) |
| `c` | int | заряд батареи, % |
| `b` | int | мощность батареи, Вт: `+` разряд, `−` заряд |
| `l` | int | нагрузка квартиры, Вт |
| `u` | int | напряжение сети, В (0, если сети нет) |
| `e` | unix сек | прогноз: при разряде — когда батарея дойдёт до порога отключения; при заряде — когда будет 100%; `0` — прогноза нет |
| `h` | сек | на сколько хватит батареи при текущем (сглаженном) потреблении квартиры до порога отключения — считается всегда, и при сети тоже; `0` — оценки нет (ёмкость не задана или нагрузка неизвестна) |
| `o` | [[a,b],…] | отключения по графику, минуты от локальной полуночи `d`; завтра = +1440; соседние интервалы склеены, отсортированы |
| `d` | unix сек | локальная (Europe/Kyiv) полночь «сегодня» |
| `w` | 0/1 | 1 — график на завтра уже опубликован |
| `m` | int | экстренные (аварийные) отключения по YASNO (статус дня `EmergencyShutdowns`): бит 0 — сегодня, бит 1 — завтра; 0 — нет. В такой день `o` пуст, виджет пишет «аварийные отключения, график не действует» |
| `t` | unix сек | когда инвертор был прочитан в последний раз; если старше 5 минут, виджет пишет «нет связи с инвертором» |

Виджет сам считает обратные отсчёты от `Date.now()`, время суток получает как `(t − d) / 60 mod 1440`,
поэтому часовой пояс устройства не важен. Бот обязан обновлять `d` и `o` после полуночи.

## Жизненный цикл сообщений

Решение от 2026-11-11: виджет — это дашборд, события — отдельные короткие текстовые сообщения.

1. Дашборд — одно живое сообщение-виджет на чат. Бот правит его `chat_data` не чаще раза в минуту
   и только если что-то изменилось, а пока связь с инвертором есть — не реже раза в 2 минуты, чтобы `t` оставался свежим.
   Если ёмкость батареи в настройках не задана, `e` всегда 0 — прогноз не показываем.
2. Сеть появилась или пропала → бот шлёт короткое обычное сообщение со звуком
   («🔴 Свет пропал в 15:02. Был 1 ч 58 мин.» / «🟢 Свет появился в 13:04. Не было 6 ч 04 мин.»),
   затем удаляет старый дашборд и беззвучно присылает новый — дашборд всегда последний в чате.
3. `/status` и кнопка «Дашборд» — беззвучно пересоздают дашборд внизу чата.
4. Дашборд старше 47 часов бот беззвучно пересоздаёт сам: своё сообщение можно удалить только в течение 48 часов,
   иначе после следующего события в чате осталось бы два дашборда.
5. Сообщение «График» (`parse_mode=HTML`, функция
   `texts.schedule_message`), после него дашборд пересоздаётся ниже, как при событии сети:
   * появился график на завтра — беззвучно («🗓 **График на завтра** · пт, 13 ноября», строки
     «с **02:00** до **07:00** · 5 ч», итог «Всего без света 17 ч»);
   * график на завтра изменился — беззвучно, «🔄 **График на завтра изменился**» и пометки в строках:
     «← было 15:00–22:00», «← было с 18:30», «← новое», отменённый интервал зачёркнут «← отменено», в итоге «(было N ч)»;
   * график на сегодня изменился — со звуком, с теми же пометками;
   * график на текущие сутки впервые опубликован уже после полуночи — «🗓 **График на сегодня**», со звуком;
   * экстренные отключения (статус дня `EmergencyShutdowns`) — со звуком: «🚨 **Экстренные отключения** · …
     График на сегодня не действует — свет отключают без расписания.» Когда график снова действует — «График на сегодня».
   Не слать: при первом запуске, при смене суток («завтра» стало «сегодня»), при ошибке/пустом ответе источника,
   при «ждём график» после опубликованного, при смене источника (YASNO ↔ запасной).
6. Кнопки — постоянная reply-клавиатура «Дашборд» / «График» / «Инвертор» (приходит с `/start`, с событиями
   и сообщениями о графике; подписчик из прошлой версии один раз получает беззвучное сообщение с кнопками).
   Нажатие (и `/status`) бот удаляет из чата. «График» — текущий график на сегодня и завтра в том же формате,
   беззвучно (прошлый такой ответ удаляется; на завтра без графика — «Ещё не опубликован.»).
   «Инвертор» — виджет «Инвертор» (ниже). После ответа на кнопку дашборд пересоздаётся внизу — он всегда последний.
7. Доступ (ниже). У всех, кому он выдан, всё одинаково: события, «График», кнопки, свой дашборд и свой виджет
   «Инвертор»; инвертор опрашивается один раз на всех, правки дашборда — не чаще раза в минуту на чат.
8. Текстовый режим (ниже): пока Telegram не разрешает виджеты, дашборд и «Инвертор» — живые текстовые сообщения
   по тем же правилам (один на чат, дашборд последний, правки не чаще раза в минуту и только при изменении).

## Текстовый режим

С 13.11.2026 17:22 Telegram на каждый `sendWidget` во всех личных чатах отвечал `400 Bad Request:
INPUT_MEDIA_WIDGET_NOT_ALLOWED`, хотя до 11:01 те же запросы проходили. По документации это не ошибка запроса:
«Widgets are rolling out in steps» (core.telegram.org/bots/widgets), «The allowed chat types are server config»
(widget-sandbox, `docs/tgw-format.md`; ошибка — «the chat is not one a bot may send widgets to»). Настройки
в BotFather, поля в `getMe` и нового параметра запроса для этого нет — бот может только ждать и проверять.

1. **Отказ запоминается.** Первый `INPUT_MEDIA_WIDGET_NOT_ALLOWED` (на дашборд или «Инвертор») — бот переходит
   в текстовый режим: в `kv.widgets` пишется `{"off": с какого момента, "probe": когда следующая проба}`, в журнал —
   одна строка «Telegram не разрешает виджеты (…) — дашборд и «Инвертор» идут текстом». Дальше события, кнопки,
   сообщения «График», `/start` и пересоздание раз в 47 ч сразу шлют текст, `sendWidget` не вызывается.
   Перезапуск режим не сбрасывает.
2. **Текстовый дашборд** (`texts.dashboard_text`, `parse_mode=HTML`, беззвучно) — то же, что «Табло»: время и
   ключевые цифры жирным, вместо обратных отсчётов — абсолютное время (текст сам не тикает):
   ```
   ⚠️ Нет связи с инвертором · данные на 17:35        ← только если t старше 5 минут
   🔴 Света нет с 17:21                                ← «🟢 Свет есть с 11:01»; старше ~22 ч — «с ср 11.11»
   По графику включат в 20:30                         ← или «Отключили вне графика — когда включат, неизвестно»,
                                                         «По графику отключат в 21:00 до 24:00»,
                                                         «По графику света нет до 20:30, но свет пока есть»,
                                                         «🚨 Аварийные отключения — график не действует»,
                                                         «До конца суток (завтра) без отключений»
   Сегодня, пт 13.11: 08:00–11:00, 17:00–20:30          ← прошедшие обычным шрифтом, остальные жирным;
   Завтра, сб 14.11: 05:00–09:00                        ← «Завтра» — только если опубликован (или аварийные)
   🔋 87% · хватит на ~19 ч, до 12:42                   ← при сети «без сети хватит на …», «полная к 18:42»;
   🏠 Нагрузка 410 Вт · сеть 229 В                         < 20 % — 🪫; «батарея полная»
   обновлено 17:42                                     ← курсивом, время правки
   ```
   Бот правит его `editMessageText` по правилам виджета: при изменении текста (кроме строки «обновлено») —
   не чаще `LIVE_INTERVAL` (60 с), пока связь есть — не реже `FRESH_INTERVAL` (2 мин), чтобы `t` был свежим.
   Связь пропала — через 5 минут одна правка «нет связи», дальше текст стоит. Пересоздаётся (удалить старый →
   беззвучно новый, он последний в чате) при тех же поводах, что и виджет. В базе `live_kind='text'`,
   `live_widget` = `texts.TEXT_FORMAT`: если формат текста поменялся (новая версия бота), уже отправленные
   текстовые дашборды исправляются на месте, без новых сообщений.
3. **Текстовый «Инвертор»** (`texts.inverter_text`) — кнопка «Инвертор» присылает сообщение с теми же данными,
   что виджет: сеть (В, Гц, из сети/в сеть Вт), дом (Вт), батарея (%, заряд/разряд Вт, В, А, °C, «хватит на»,
   «отключится при 10%», «полная к»), температура инвертора, «За сегодня, кВт·ч». Один на чат (прошлый удаляется),
   правится 15 минут по правилам виджета (`INVERTER_INTERVAL`, `FRESH_INTERVAL`), внизу «обновлено HH:MM ·
   обновляется до HH:MM»; после `z` — одна последняя правка «Снимок на HH:MM · свежие данные — кнопка «Инвертор»».
   Дашборд после него пересоздаётся ниже. В базе `inv_kind='text'`.
4. **Проба** — раз в `WIDGET_PROBE_MINUTES` (30) одна попытка `sendWidget` на всех:
   * если в это время дашборд пересоздаётся (событие, кнопка) — проба и есть это пересоздание: отказ → текст,
     как обычно;
   * иначе — в чате владельца (если у него текстовый дашборд и чат в порядке, иначе у следующего подписчика):
     новый виджет-дашборд шлётся под текущим текстовым, и только если Telegram его принял, текст удаляется.
     Отказ в чате ничего не меняет — ни лишних сообщений, ни мигания; в журнал (DEBUG) — без предупреждений.
   * текстовых дашбордов нет ни у кого — проба откладывается на следующие 30 минут.
5. **Возврат.** Проба прошла — в журнал одна строка «Telegram снова разрешает виджеты — текстовые дашборды
   заменяются виджетами», `kv.widgets.off = null`, у всех с текстовым дашбордом он беззвучно пересоздаётся
   виджетом при ближайшей сверке. Текстовый «Инвертор» доживает свои 15 минут.
6. **Выкатка этой версии** на базу, где дашборды уже текстовые, а `kv.widgets` ещё нет: бот считает, что виджеты
   запрещены, и сразу делает одну пробу (п. 4). Отказ — текстовые дашборды исправляются на месте новым форматом;
   разрешено — заменяются виджетами.
7. Другая ошибка `sendWidget` (не `INPUT_MEDIA_WIDGET_NOT_ALLOWED`, не 429/5xx) режим не меняет: этот один дашборд
   или «Инвертор» приходит текстом (тоже живым), при следующем пересоздании бот снова пробует виджет.

## Доступ

Владелец — `OWNER_ID`, а если не задан — первый id в `ALLOWED_IDS`. `ALLOWED_IDS` — изначальный список доступа;
решения владельца хранятся в базе (таблица `access`) и важнее списка. Владелец доступ не теряет.

1. Человек без доступа пишет боту что угодно → ему «Запрос отправлен владельцу. Как только он подтвердит — бот
   заработает.», владельцу со звуком — «Имя Фамилия (@username) просит доступ к боту» (без username — «(id 123)»)
   с inline-кнопками «Разрешить» / «Отклонить». После запроса дашборд владельца пересоздаётся ниже.
2. Пока запрос не решён, следующие сообщения этого человека молча игнорируются (запрос один).
   Новых запросов — не больше `ACCESS_PER_HOUR` (3) в час на всех, остальные молча игнорируются.
3. «Разрешить» → сообщение владельца правится на «Доступ выдан: Имя» (кнопки исчезают); человеку —
   «Доступ открыт. Пришлю сообщение, когда свет пропадёт или появится; кнопки внизу: «Дашборд», «График»,
   «Инвертор».» с клавиатурой и сразу беззвучно дашборд. Событие о текущем состоянии сети ему не шлётся.
4. «Отклонить» → «Отклонено: Имя» у владельца, человеку — «Доступ не выдан.»; дальше он игнорируется молча.
5. Кнопки нажимать может только владелец (проверяется `from.id` в `callback_query`), остальным — всплывающее
   «Это может только владелец бота.» Повторное нажатие — «Уже решено.»
6. `/users` (только владелец) — список «С доступом» (у каждого, кроме владельца, кнопка «Убрать · Имя»),
   «Ждут ответа» и «Без доступа» (кнопка «Разрешить · Имя»). Список правится на месте после нажатия.
   «Убрать» → бот удаляет дашборд и виджет «Инвертор» этого человека (если может), больше ему не пишет
   и молча игнорирует его сообщения; вернуть доступ — «Разрешить» в `/users`.
7. Владелец не задан (`ALLOWED_IDS` пуст) — запросов нет, бот отвечает отказом с id человека, как раньше.

## Виджет «Инвертор» (`widgets/inverter.html`)

Отдельное сообщение по кнопке «Инвертор»: схема «Сеть → инвертор → Дом, инвертор ↔ Батарея», батарея, сеть,
температура инвертора, «за сегодня». Один на чат: повторное нажатие удаляет прошлый. Бот правит его
`INVERTER_MINUTES` (15) минут: при изменении — не чаще `INVERTER_INTERVAL` (30 с), `t` — не реже 2 минут, пока связь
есть. Пока виджет живой, дневной блок регистров читается раз в 30 с (иначе раз в 5 мин). После `z` сообщение
остаётся снимком — виджет сам пишет «Снимок на HH:MM · свежие данные — кнопка «Инвертор»».

| ключ | тип | смысл | регистр |
|---|---|---|---|
| `r` | int | ревизия этого сообщения | — |
| `t` | unix с | время чтения инвертора; старше 5 мин → «нет связи» (или «снимок», если прошёл `z`) | — |
| `d` | unix с | локальная полночь «сегодня» (для HH:MM) | — |
| `z` | unix с | до какого момента бот обновляет сообщение | — |
| `g` | 0/1 | сеть есть (тот же порог, что в дашборде) | 150 |
| `u` | float, 1 знак | напряжение сети, В; 0 без сети | 150 |
| `f` | float, 2 знака | **необязательный**, частота сети, Гц; только при сети (без сети ключа нет) | 79 |
| `n` | int | **необязательный**, мощность сети, Вт: `+` из сети, `−` в сеть; 0 без сети | 169 |
| `l` | int | нагрузка дома, Вт | 178 |
| `c` | int | заряд, % | 184 |
| `b` | int | мощность батареи, Вт: `+` разряд, `−` заряд | 190 |
| `a` | float, 1 знак | ток батареи, А, знак как у `b` | 191 |
| `v` | float, 1 знак | напряжение батареи, В | 183 |
| `k` | float, 1 знак | температура батареи, °C | 182 |
| `x` | int | порог отключения, % | 217 |
| `h`, `e` | | как в дашборде | — |
| `i` | float, 1 знак | **необязательный**, температура радиатора инвертора, °C | 91 |
| `q` | [float×4] | **необязательный**, за сегодня, кВт·ч: `[заряд, разряд, из сети, потребление]` | 70, 71, 76, 84 |

Необязательные ключи виджет не показывает, если их нет. Какие регистры шлются — `svitlo/state.py`
(`INV_GRID_POWER`, `INV_GRID_HZ`). Сверка на живом инверторе 12.11.2026 13:28 (сети нет, разряд 182 Вт): 91 → 40,6 °C,
90 → 56,0 °C (DC-трансформатор, не выводится), 154/156 → 230,0 В и 157 → 233 В на выходе (не выводится),
59 = 2 (норма), 101–106 = 0 (ошибок нет; в виджете места нет — не выводится), 192 → 50,00 Гц на выходе,
79 = 0 и 169 = 0 без сети, ток 191 положительный при разряде (как `b`); счётчики сходятся:
из сети 7,7 ≈ потребление 7,1 + заряд 1,9 − разряд 1,3 кВт·ч.
Сверка при сети 12.11.2026 16:08–16:10 (6 отсчётов через 20 с, сеть 224–226 В, SOC 100 %, дозаряд 150–262 Вт):
169 = +751…+850 Вт при нагрузке 178 = 595–637 Вт — это нагрузка + заряд (178 − 190) с разницей 7–12 Вт (потери),
знак «+» = из сети, то же значение в 167; 79 = 49,98–50,01 Гц (192 на выходе — 49,98–50,01); 150 = 154 (224,5 В);
ток 191 отрицательный при заряде, 183 × 191 = 190; 91 → 46,2–47,1 °C; счётчики: из сети 9,2 = потребление 8,3 +
заряд 3,1 − разряд 2,2 кВт·ч. Поэтому `n` и `f` шлются (`INV_GRID_POWER = INV_GRID_HZ = True`).

Примеры (без сети ≈ 190 байт, при сети ≈ 200 байт; лимит 1024):

